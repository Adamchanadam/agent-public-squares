APS 單機 UX Transcript 矩陣

這頁是 APS 真雙機測試前的單機 UX 驗收工作台。目標不是建立一套標準，而是證明非技術新手只用自然語言向 AI 說目的，也能完成 APS 核心合作流程。它把非技術用戶會說的話、合格 AI 第一屏、AI 背後應做、不可出現文字、通過條件與證據狀態分開，避免把命令能跑或標準存在誤讀成用戶旅程已成熟。

真源定位

本頁跟隨 APS 全流程地圖。流程地圖管整體旅程與階段；本頁管每個高風險入口的第一屏 transcript 與單機 UX 證據。

本頁不取代 CLI 行為真源 bin/aps.js，不取代 PUBLIC executable regression dev/qc/check_context_index.cjs，也不取代 OPS 覆蓋登記 dev/qc/QC_COVERAGE_INDEX.md。頁內標示「已有命令證據」只代表底層功能曾驗過，不代表第一屏 UX 已通過。

使用規則

先看第一屏。

用戶貼邀請或說目的後，AI 第一個可見回覆必須讓非技術人員知道下一步，不應先倒出內部模型或命令。

正常情況直接建議。

沒有讀到衝突時，AI 直接建議加入、檢查或補共同基準；只有真的讀到不同 APS 交換區、不同 APS 合作目錄或多邀請時才解釋衝突。

證據分層。

頁內把第一屏規格、fixture、本機證據、外部 gate 分開。不可用 CLI regression 取代新手可見的第一屏判斷。

逐條清零。

每次補一條情景，都要更新本頁該行、PUBLIC 測試錨點、OPS 覆蓋登記或熱圖；不在 handoff 內暫存長期規則。

證據狀態

真人 UAT gate單機 fixture 已覆蓋後，仍需真人檢查第一屏是否自然可懂。
需補 fixture第一屏文字已定，但仍欠可重跑的單機 fixture 或 regression。
已有本機證據已有本機可執行或直接檢查證據；仍不等於真人或真雙機通過。
外部 gate需要真人、兩部實體機、真 Drive timing 或外部通知證據。

APS Live 功能與分支覆蓋

本表把 APS Live 由「一個頁面」拆成可驗收功能與分支。正常用戶不需要看內部房間、封包或命令；AI 只應在狀態卡住、資料不足、共同基準未確認或需要即時核對時打開 Live。

功能 / 分支合格行為不可出現證據
第一次 Check APS 入口先顯示 APS 交換區、APS 合作目錄、本機用戶名稱、協作者狀態與共同基準狀態；沒有阻塞時直接給下一句可做的事。把 check Drive 當整體狀態；直接叫用戶輸入命令。aps-ux-check-aps-live-branches-fixture.json
沒有共同基準顯示「共同基準：未通過 / 需處理」與「需先建立共同目標與分工」；普通任務不可開始；回到本機 AI 建立共同目標與分工草稿。「共同基準：已完成」；未有共同基準仍說可以開工。同上；對齊 APS Live spec no-baseline row。
共同基準草稿未確認共同基準是「共同基準：進行中」；提供同意、部分同意、有異議、稍後四種回 terminal 路徑。把草稿當正式基準；直接發普通交接。同上。

不可出現清單

以下任何一項出現在正常第一屏，即視為 UX 失敗。
  • 要求非技術用戶自己輸入 npx 作主流程。
  • 預設建議更換、另開或改建本機工作目錄。
  • 把本機工作目錄說成 APS 合作目錄。
  • 把 APS 交換區的本機路徑當成雙方相同。
  • 照抄發起人的 Google Drive 本機路徑給受邀者。
  • 要求邀請人先知道或替受邀者設定用戶名稱。
  • 正常情況先講互邀衝突、內部風險或 A / B 選項。
  • 把邀請碼說成房間、身份、共同目標或正式交接。
  • 把資料不足退回說成完成。
  • 把 APS Live 訊息當作正式 ack 或正式完成紀錄。
  • 把 APS Live 當成自動 consume、decline、revise、close、publish 或 ack 的地方。
