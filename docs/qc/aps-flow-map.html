產品流程 · 完成度檢查

APS 全流程地圖與完成度檢查表

這頁用來決定 APS 是否已成熟到值得做真人或雙機測試。合格標準不是「命令能跑」，而是非技術用戶用自然語言提出目的後，AI 能穩定完成整條合作流程。

真源定位

本頁是 APS 產品旅程與完成度安排的真源。凡改動 APS 使用者流程、功能邏輯、階段順序、完成度判斷或工作優先級，必須同步更新本頁、APS 單機 UX Transcript 矩陣內的「新手非技術 UX 驗收軸」，再同步 QC 覆蓋登記與熱圖。

本頁不取代其他真源：CLI 實際行為以 bin/aps.js 為準；可執行回歸以 dev/qc/check_context_index.cjs 為準；QC 覆蓋狀態、缺口與阻塞以 OPS dev/qc/QC_COVERAGE_INDEX.md 為準；單機第一屏與用戶語句驗收以 APS 單機 UX Transcript 矩陣 跟隨本頁補齊。

驗收語彙防誤讀

本頁的狀態只描述證據層級，不代表所有 UAT 已通過。對外讀法固定為：本機已驗、AI 代理已驗、真人未驗、兩機未驗、外部受阻、不適用。任何「本機已驗」都只表示可重跑 fixture、回歸或本機證據存在；不能替代真人普通用戶理解，也不能替代真兩機、真 Drive timing 或 APS Live transport。

通用產品準則

以下準則適用於整個 APS，不只適用於邀請協作者。

用戶講目的，AI 做技術。

正常入口應是「邀請協作者」、「Check APS」、「check Drive」、「把這段交給對方」這類目的語句。命令列存在，但不應成為非技術用戶的主操作方法。

單機產品級完成，才推雙機；只可最後做雙機。

雙機測試成本高，只應在單機流程、真 Drive 本機煙霧測試、用語、負向變體與 UX transcript 都收口後才做。

新手 UX 是產品結果閘。

非技術新手只講目的時，AI 必須能帶他完成安裝 / 加入、Check APS、共同基準、正式交接、收件、退回、修訂與收結。目標是完成整條合作流程，不是只建立驗收標準；未過這一軸，不可宣稱產品旅程成熟。

發現一個坑，要查鄰近變體。

若用戶測到一個錯誤，不可只補該句文字；要檢查相鄰入口、同義語、既有設定、互邀、重名、Drive 路徑、收件與退回等同機可驗變體。

全流程圖

每一格代表用戶眼中的一步。AI 背後可讀 HTML、跑 CLI 或檢查檔案，但不把技術步驟推給用戶。

1. 選本機工作目錄

用戶在平日處理該項目的本機工作目錄打開 agentic AI。

不得把本機工作目錄與 Google Drive APS 交換區混為一談。
2. 安裝或升級 APS

AI 讀安裝頁、檢查現況、提出一次性計劃，確認後連續執行。

已有 .aps/config.json 走升級，不重建。
3. 建立 APS 交換區

Google Drive 共用資料夾是同步地方；每部機的本機路徑可不同。

不得把發起方路徑交給受邀方照抄。
4. 建立 APS 合作目錄

合作目錄等同這次合作的房間，名稱應與任務或項目有關。

不要用人名、電腦名、AI 名稱或發起人名稱。
5. 建共同目標與分工

先確定共同目標、角色、第一輪分工、驗收標準與不可做的事。

未有共同基準，不應先發普通任務。
6. 邀請協作者

發起人只需說「邀請協作者」。AI 生成可轉發邀請；對方用戶名稱由對方自己定。

peer add 只屬維護或兼容。
7. 受邀者加入

受邀者貼上邀請後，AI 讀邀請、檢查設定、正常情況直接建議加入。

只有發現衝突才解釋衝突。
8. Check APS 基準確認

加入後先看整體狀態、共同基準、協作者與下一步。

Check APS 是整體狀態；check Drive 是讀具體收件。
9. 發正式交接

發送方整理交接確認卡，補齊真源、開工條件與風險，經用戶確認才寫 Drive。

正式交接每次仍是一對一。
10. 收件方 check Drive

收件方 AI 摘要對方交來甚麼，做完整性與本機對接檢查。

收到 packet 不等於可以立即開工。
11. 判斷可開工或退回

資料足夠才處理；不足則發補交需求或共識確認。

未補齊前不把原交接收結。
12. 修訂、回覆與收結

發送方 revise / withdraw / close；收件方 consume / decline / reply，狀態可追蹤。

舊版本不可被當作最新任務。
13. 多人逐一交接

同一 APS 合作目錄可有多位用戶，但每個 packet 只發給一位。

不能讓 B 看見或消化 C 的 packet。
14. APS Live 交接工作台

Live 在交接期間顯示階段、下一位行動者、即時對齊和回本機 AI 的主出口；正式狀態仍回到 terminal / 本機 AI 經用戶確認落帳。

Live 不取代 Drive 帳本，也不自動 publish。
15. 升級維護

既有項目更新套件、跑 upgrade、再 doctor。

不得覆寫既有交接、ack、peer 或共同基準。
16. 最後才做真雙機

單機流程與 UX 變體收口後，才安排真人或兩部實體機測試。

雙機測試不是補單機設計粗疏的工具。
