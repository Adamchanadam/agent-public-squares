給本機 AI 代理讀

帶用戶安裝與設定 Agent Public Squares

本頁不是給普通聊天 AI 使用。你必須是能讀寫本機項目資料夾、能執行終端機命令、能上網核對文件的本機代理型 AI，例如 Codex 或 Claude Code。

任務定位

你的任務是帶非技術用戶在目前本機項目資料夾安裝並設定 Agent Public Squares。用戶會提供三項資料：Google Drive 本機路徑、項目代號、自己的 agent id。你不可猜測這三項。

安全邊界：任何會安裝套件、寫入檔案、修改設定、寫入共用 Drive 資料夾、提交、推送或發佈的動作，必須先列出將會做甚麼、影響哪些路徑，並取得用戶確認。不要自動替用戶發出 APS 交接包，不要改 Google Drive 權限，不要代發外部訊息。

用戶可複製的起步 prompt

若用戶未提供明確任務，可要求他把以下整段貼給本機代理型 AI。

請在目前本機項目資料夾，按這頁指引帶我安裝和設定 Agent Public Squares：
https://adamchanadam.github.io/agent-public-squares/docs/guides/aps-ai-agent-install.html

你要先讀完整頁面，再檢查目前資料夾是否適合安裝。任何會安裝套件、寫入檔案、修改設定或寫入共用 Drive 資料夾的步驟，先列出將會做甚麼，等我確認後才執行。Google Drive 本機路徑、項目代號、我的 agent id 由我提供。

先做只讀檢查

  1. 確認能力。如果你不能讀寫本機資料夾或不能執行命令，停止並告訴用戶要改用 Codex、Claude Code 或同等本機代理型 AI。
  2. 確認工作目錄。顯示目前資料夾路徑，問用戶是否就是要安裝 APS 的項目資料夾。不要在不明根目錄安裝。
  3. 檢查是否已有 Agent Handoff Kit。只讀檢查是否有 AGENTS.md、dev/RULE_PACKS.md、dev/PROJECT_INDEX.md。缺少時，下一步才建議初始化；已存在時，不要重複初始化，先跑健康檢查，必要時才建議升級。
  4. 檢查是否已有 APS。只讀檢查是否有 .aps/config.json。已有者走升級路徑，沒有者走新安裝路徑。
  5. 向用戶收集三項資料。Google Drive 本機路徑、項目代號、自己的 agent id。提醒項目代號和 agent id 只能用小寫英文、數字與底線。
  6. 確認 Google Drive 目標資料夾可離線使用。請用戶在 Windows 的 Google Drive 目標資料夾按右鍵，選 顯示其他選項 → 離線存取 → 可離線使用。這一步由用戶在檔案總管確認；你不要改 Google Drive 權限，也不要猜測同步狀態。

新安裝路徑

只有在目前項目沒有 .aps/config.json 時使用。這條路仍要先分清楚 Agent Handoff Kit 是否已存在。

  1. 列出安裝計劃：會檢查 Agent Handoff Kit、安裝 npm 套件、執行 APS init、寫入本機設定與共用 Drive 資料夾骨架。若 Agent Handoff Kit 已存在，計劃中要寫明不會重複初始化。
  2. 如果缺少 Agent Handoff Kit，取得用戶確認後才執行初始化。命令如下： 
    npx --yes @adamchanadam/agent-handoff-kit@latest init
  3. 如果已有 Agent Handoff Kit，先做健康檢查；如檢查顯示需要升級，先列出會改動的治理檔，取得用戶確認後才執行升級。命令如下： 
    npx --yes @adamchanadam/agent-handoff-kit@latest doctor --root <目前項目資料夾>
npx --yes @adamchanadam/agent-handoff-kit@latest upgrade --root <目前項目資料夾>
    若升級工具要求輸入 yes，必須先向用戶確認，再輸入 yes。
  4. 取得用戶確認後，安裝 APS 套件。命令如下： 
    npm install --save-dev @adamchanadam/aps@latest
  5. 執行 APS 初始化。優先使用互動式 npx aps init，按用戶提供的三項資料回答。若你需要非互動方式，使用： 
    npx aps init --hub-root "<Google Drive 本機路徑>" --project <項目代號> --agent-id <自己的 agent id>
  6. 工具列出寫入計劃時，轉述給用戶確認，確認後才輸入 yes。
  7. 完成後跑健康檢查： 
    npx aps doctor

既有項目升級路徑

如果已有 .aps/config.json，不要重建共用 Drive 資料夾。

  1. 讀取 .aps/config.json，向用戶摘要目前項目、共用 Drive 資料夾、自己的 agent id。
  2. 取得確認後，更新 npm 套件： 
    npm install --save-dev @adamchanadam/aps@latest
  3. 取得確認後，刷新 APS 橋接與技能： 
    npx aps upgrade
  4. 跑 npx aps doctor，把結果翻譯成普通用戶看得懂的狀態。

成功判斷

檢查成功標準
Agent Handoff Kit目前資料夾有 AGENTS.md、dev/RULE_PACKS.md、dev/PROJECT_INDEX.md；新項目已初始化，既有項目已健康檢查，必要升級已經用戶確認。
APS 本機設定存在 .aps/config.json，內容指向用戶提供的共用 Drive 資料夾、項目代號與自己的 agent id。
共用 Drive 資料夾npx aps doctor 通過；未邀請對方時，對方狀態只可作參考，不應視為失敗。
狀態入口用戶說 Check APS 時，讀取整體 APS 狀態：收件、發件、協作對象、風險與按需 dashboard。不要把它說成背景自動監察。
下一步先帶用戶建立「項目共同簡報」，確認共同目標、參與者、角色、第一輪分工、不可做事項與驗收標準；共同簡報確認後，才建議邀請協作者或建立第一輪交接。示範人名不得當作固定預設。

安裝後：先建立項目共同簡報

這是安裝成功後的第一個產品流程。不要直接叫用戶邀請對方或發測試包，先把團隊共同口徑定好。

  1. 向用戶說明用途。共同簡報會成為之後邀請 peer、發第一輪交接包、以及對方 check Drive 時判斷能否接手的基準。
  2. 由 AI 先整理草稿。從用戶已提供的項目背景、目前資料夾內容和對話中整理；缺資料才問，最多問三個關鍵問題。
  3. 共同簡報至少包含：共同目標、參與者與 agent id、每人角色、第一輪分工、不可做的事、驗收標準、第一個邀請對象、第一輪交接對象。
  4. 不要硬套示範人名。實際參與者、角色和 agent id 必須由用戶提供，或由 AI 整理後交用戶確認。
  5. 可以加欄。八項是最低欄位；若項目需要截止日期、優先級、參考檔、品牌語氣、審批點、合規限制、輸出格式、語言、預算或時間限制，可以加入，但不要刪除核心欄位。
  6. 先讓用戶確認。確認共同簡報內容、第一個邀請對象、以及可否作為後續邀請和第一輪交接的基準。
  7. 確認後才進入下一步。若對方未加入，走邀請流程；若對方已加入，才用共同簡報加上對方任務建立第一輪交接草稿。
請先幫我建立這個 APS 項目的共同簡報，再邀請協作者。共同簡報要包括共同目標、參與者與 agent id、每人角色、第一輪分工、不可做的事和驗收標準。參與者和 agent id 由我確認；如項目有額外要求，可以加欄，但不要刪除核心欄位。

出錯處理

  • Google Drive 路徑不存在：請用戶在檔案總管或 Finder 打開共用資料夾，重新複製完整路徑。不要使用含 ... 的省略路徑。
  • npm 或 npx 失敗：先讀錯誤訊息。若是網絡、權限或快取問題，說明原因並請用戶確認是否允許重試；不要改用危險命令。
  • doctor 未通過：不要手寫共用 Drive 檔案。先核對 .aps/config.json、共用 Drive 路徑和項目代號。
  • 普通聊天 AI 無法操作：明確告訴用戶要改用本機代理型 AI，因為普通聊天 AI 不能讀寫本機項目資料夾。

收尾輸出

完成後，用簡短中文回報：

  • 安裝是否成功。
  • 目前項目代號與自己的 agent id。
  • doctor 是否通過。
  • 下一句建議用戶說甚麼：先說「請幫我建立這個 APS 項目的共同簡報」，共同簡報確認後才邀請實際協作者或建立第一輪交接；日後要看整體狀態可說 Check APS。
