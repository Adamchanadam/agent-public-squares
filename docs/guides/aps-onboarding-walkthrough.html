第一次安裝 APS：把工作交給本機 AI 代理。

這頁給非技術用戶看。你不用先理解命令，也不用手動改設定檔。你只要打開能操作本機資料夾的 AI 代理，把指定 prompt 貼給它，然後按它提示確認。

第一步：選對 AI 工具

你需要的是本機代理型 AI，例如 Codex、Claude Code 或同等工具。它要能做到三件事：讀寫目前項目資料夾、執行終端機命令、讀網頁。

普通網頁聊天不適合直接安裝。如果 AI 不能操作你的本機資料夾，它只能解釋步驟，不能替你完成安裝。

第二步：打開你的本機項目資料夾

在你的電腦上準備一個工作資料夾，用來放這個項目的本機檔案。不要把工作資料夾放在 APS 共用 Drive 資料夾裏面。然後在這個工作資料夾打開 Codex、Claude Code 或同等 AI 代理。

第三步：把 Google Drive 共用資料夾設為可離線使用

APS 會把交接包寫入 Google Drive 同步到本機的共用資料夾。為了減少同步延遲和「看得到資料夾但檔案未落地」的問題，請先把這個共用資料夾設為可離線使用。

在 Windows 下，到 Google Drive 的目標資料夾，按右鍵，選 顯示其他選項，再選 離線存取，最後選 可離線使用。

第四步：貼上這段話

請在目前本機項目資料夾，按這頁指引帶我安裝或加入 Agent Public Squares（APS）：
https://adamchanadam.github.io/agent-public-squares/docs/guides/aps-ai-agent-install.html

你要先讀完整頁面，再檢查目前資料夾是否適合安裝或加入。若目前資料夾已有 .aps/config.json，請先讀取並比對項目代號與共用 Drive 路徑，不要直接覆寫。任何會安裝套件、寫入檔案、修改設定或寫入共用 Drive 資料夾的步驟，先列出將會做甚麼，等我確認後才執行。Google Drive 本機路徑、項目代號、我的 APS 名稱由我提供或確認；如果我是受邀加入，項目代號以邀請訊息為準，APS 名稱仍由我自己決定，請先檢查是否重名。

你要準備的三項資料

AI 代理會問你，不用現在填在網頁上。

資料意思例子
Google Drive 本機路徑你電腦上同步出來的 APS 共用資料夾完整路徑。G:\我的雲端硬碟\Agent_Public_Squares
項目代號這次合作項目的短名。雙方要一樣。branding_2026
你的 APS 名稱你自己在這個共用資料夾裏的身份。每個人填自己；普通邀請不會替你預先取名，例子不可當作固定預設。owner、reviewer
APS 名稱不是隨手暱稱。它是共用 Drive 資料夾裏的共享身份。每個人要使用由本人確認、且在項目裏不重名的固定名稱，例如一邊叫 owner，另一邊叫 reviewer；兩邊不要都把自己叫 agent_a。

過程中你會看到甚麼？

  • AI 代理會先檢查目前資料夾是否適合安裝。
  • 它會檢查目前資料夾有沒有 Agent Handoff Kit；沒有才初始化，已有就先健康檢查，必要升級時會先問你。
  • 它會列出將要安裝甚麼、寫入哪些檔案、使用哪個共用 Drive 資料夾。
  • 你確認後，它才會執行命令。
  • 最後它會跑健康檢查，告訴你是否成功。
請不要跳過確認。安裝套件、寫設定、寫入共用 Drive 資料夾之前，都應該先由你確認。

成功之後下一句說甚麼？

先不要急着邀請對方或發測試包。第一位用戶應先叫 AI 建立「共同目標與分工」，把共同目標、參與者、角色、第一輪分工、不可做的事、驗收標準、第一個邀請對象和第一輪交接對象定好。這是這個 APS project 的目前有效基準，不是每位用戶各自一份的私人草稿；可以修訂出新版本，但不應平行存在兩套互相打架的口徑。人名和 APS 名稱由你提供或確認；示範名稱不可當作固定預設。

請先幫我建立這個 APS 項目的共同目標與分工，再決定是否邀請或發給協作者確認。

共同目標與分工確認後，AI 應先問你是否本機保存、發給 confirmed peer 確認，或先邀請對方。若有三位或以上協作者，同一份基準要逐一發給受影響協作者確認；後加入協作者要先收到最新版，不應自行重建。若只是普通 bugfix、補資料、審閱或單次交付，用普通交接包或修訂包處理，不要把每個任務變更都升格成共同目標修訂。若你要找人一起協作，可以對 AI 說：

邀請我指定的協作者加入這個 APS 項目。

如果對方已經接好，你可以先做一次測試：

幫我發一個 APS 測試交接給我指定的協作者，內容只寫「APS setup test」。

如果對方說他已經發了東西給你，你只要說：

check Drive

如果你想看整個 APS 項目的狀態，包括你收到的、你發出的、協作對象和風險，可以說：

Check APS

這是按需檢查，只整理本機已同步資料中的下一步與風險，不是自動派工，也不是背景自動監察；仍然不會自動通知或打開對方的 AI。

人工備用命令

一般新手不用自己打。只有在 AI 代理要求你手動執行，或你想排錯時才看這段。

npx --yes @adamchanadam/agent-handoff-kit@latest init --dry-run --root "<目前項目資料夾>"
npx --yes @adamchanadam/agent-handoff-kit@latest init --yes --root "<目前項目資料夾>"
npm install --save-dev @adamchanadam/aps@latest
npx aps init --dry-run
npx aps init --hub-root "<Google Drive 本機路徑>" --project <項目代號> --agent-id <自己的_APS_名稱>
npx aps doctor

不要用 npx aps init --help 查用法；查用法請用 npx aps --help。非互動終端先用 --dry-run 預覽，正式設定時帶齊 --hub-root、--project、--agent-id。
