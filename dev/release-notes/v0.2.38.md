## Agent Public Squares v0.2.38

這版補上三人協作情境下的正式交接邊界：同一個 APS 合作目錄可以有多位已確認協作者，但每一份正式 packet 仍然只交給一位收件人。當 Jay 在三人專案中主導交接時，APS 必須清楚證明他可以指定 Adam 收件，而 Fanny 作為非收件人不會看到或處理這份正式交接。

### 主要更新

- PUBLIC regression 新增 Jay 主導三人專案的情境覆蓋。
- 測試確認 `peers` 可以顯示 Adam、Jay、Fanny 三位已確認協作者。
- 測試確認 Jay 發出的正式 packet 只寫給 Adam，不會同時寫給 Fanny。
- 測試確認 Adam 的 `check Drive` 可以看到 Jay 發來的正式交接正文。
- 測試確認 Fanny 的 `check Drive` 不會看到 Adam-targeted packet 的主題或正文。
- 測試確認 Jay 的 `Check APS` 會顯示等待 Adam，而不是誤顯示交給 Fanny。

### 驗收狀態

- PUBLIC regression 已通過，包含 `PASS jay-led three-person group keeps formal handoff one-to-one`。
- 本次發佈流程包含 source syntax、PUBLIC regression、npm pack、npm publish、GitHub tag / release、npm / npx / remote / Pages 讀回。
- 這版加強的是 developer-validation 層的多協作者一對一 packet 邊界，不等同已完成真實三人 UAT、獨立多機同步證明、APS Live transport 證明或外部通知證明。

### 使用邊界

APS 支援一個合作目錄中有多位已確認協作者，但正式交接仍是一對一 packet。多人協作時，請先確認共同目標與分工，再按每一輪實際需要選定單一收件人；非收件人不應被當成已收到、已讀取或可處理該 packet。
