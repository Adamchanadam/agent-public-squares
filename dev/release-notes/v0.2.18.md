# Agent Public Squares v0.2.18 — Check APS status surface

Status: release-ready source for `@adamchanadam/aps@0.2.18`.

## What changed

- Added `npx aps check-aps` as the whole-project APS status command.
- `Check APS` now shows a conversation-readable status surface covering incoming handoffs, sent handoffs, collaborators, and risks.
- `check-aps` refreshes `_context/dashboard.html` on demand.
- `check Drive` remains the receiver-side inbox check; it is not replaced by `Check APS`.
- The APS skill now treats `Check APS`, `check-aps`, `檢查 APS 狀態`, and `APS 狀態` as narrow APS status triggers.
- Generic `status`, `check`, `交接包`, and `收工` must not be captured as APS status triggers.
- README, public teaching pages, AI install guidance, joiner guidance, roadmap, QC standards, and sync registry now describe the status-surface boundary.

## User effect

A user can say:

```text
Check APS
```

The AI should show what needs attention, what the user has sent, which collaborators are visible, and what risks remain. The result is a local, on-demand view of synced files. It is not background monitoring and it does not prove that another person received a notification.

## Boundary

- This release does not add automatic notification, background watch, bot sending, group chat, or multi-recipient packets.
- `Check APS` is an on-demand status surface only.
- `check Drive` remains the receive-side handoff check.
- Agent Handoff Kit session closeout remains separate from APS cross-machine handoff packets.
