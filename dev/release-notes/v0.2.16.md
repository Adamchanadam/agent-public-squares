# Agent Public Squares v0.2.16 — Strict handoff intake

Status: release-ready source for `@adamchanadam/aps@0.2.16`.

## What changed

- Added a formal `--strict-handoff` gate for `aps publish`.
- Formal one-sentence handoff now requires a complete handoff definition before writing to the shared Drive folder.
- The CLI blocks strict handoffs that miss common goal, sender task, receiver task, handoff point, machine-readable `--items`, evidence, or risks.
- Strict handoff now checks section content, not headings only. Empty sections and placeholder-only core fields such as `未確認`, `TBD`, or `N/A` do not pass for common goal, sender task, handoff point, evidence, or other core fields.
- Non-strict publish still works for short tests and older flows, but prints a warning when the handoff body is incomplete.
- APS skill and public docs now tell AI agents to build a handoff definition card, fill reliable gaps from context, ask at most a few key questions, and avoid sending incomplete formal packets.

## New-user effect

A user can still say:

```text
幫我用 APS 整理交接包給 Jay，請她接手下一步。
```

The AI should treat this as an intake request, not as proof that the packet is ready. It should identify Jay, her role in this task, the shared goal, the sender's completed work, the exact action requested, the evidence location, boundaries, and risks before publishing.
