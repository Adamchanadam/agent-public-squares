# Agent Public Squares v0.2.24

This release publishes the local-supported APS Live product-standard work and the related QC hardening needed before two-machine validation.

## What Changed

- Added APS Live as a local-supported handoff-tracking and exception-coordination layer in the APS product model.
- Kept formal APS truth in terminal / local AI: Live can clarify and queue follow-up material, but cannot publish, consume, decline, revise, withdraw, close, or ack by itself.
- Retired the old HTML dashboard path from the current product story; daily status remains `Check APS`, with APS Live generated only when live clarification is useful.
- Added local AI queue bridge support for APS Live follow-up items.
- Strengthened post-join peer confirmation so a confirmed joining peer is not downgraded back to provisional before the first shared baseline.
- Expanded strict handoff safeguards for receiver-readable source pointers, receiver start conditions, and likely secret strings.
- Updated README, public guides, maintainer docs, QC docs, and the bundled APS skill wording to match the current product boundary.

## QC Evidence

- PUBLIC `npm test` passes, including APS Live boundary checks, post-join peer confirmation, strict handoff secret-pattern samples, dialogue-draft quality checks, public-doc alignment checks, and lifecycle matrix coverage.
- Local same-machine six-stage APS Live product-flow evidence exists in OPS governance evidence.
- Local package-install substitute validation exists in OPS governance evidence.
- Zero-knowledge AI-persona substitute validation exists through first shared baseline and first ordinary handoff.

## Boundaries

- This is not true two-machine / independent-network APS Live proof.
- This is not real human zero-knowledge UAT.
- This is not external notification delivery proof.
- APS Live should be described as local-supported and suitable for the next two-machine validation round, not as reliable cross-machine support yet.
